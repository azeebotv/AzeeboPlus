## Feature 2: Content Geo Restriction

**Goal:** Server-based content filtering by geographic region, content ratings, and licensing compliance.

### What Exists
- `AccessControlService` in content-service handles rental/pass/screening access (no geo logic)
- No IP geolocation in codebase
- Content model has no geo or rating fields
- Gateway has middleware pipeline (auth, rate limiting)

### Implementation

#### 2A. Geo Database Schema
**File to modify:** `services/core/content-service/prisma/schema.prisma`

**Add to ContentItem:**
```prisma
allowedCountries  String[]  // ISO country codes; empty = worldwide
blockedCountries  String[]  // Countries where content is blocked
contentRating     String?   // "G", "PG", "PG-13", "R", "NC-17", "18+"
minAge            Int?      // Minimum age requirement
```

**New table:**
```prisma
model GeoRestriction {
  id              String   @id @default(uuid())
  countryCode     String   // ISO 3166-1 alpha-2
  countryName     String
  isActive        Boolean  @default(true)
  blockedContent  String[] // Content IDs or categories
  notes           String?
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
  @@map("geo_restrictions")
}
```

#### 2B. Geo Detection Service
**New file:** `packages/security/src/geo-detection.service.ts`

**Approach:** Use request headers (`CF-IPCountry` from Cloudflare, `X-Forwarded-For`) + free GeoLite2 database (MaxMind) for IP-to-country resolution.

**Logic:**
1. Check `CF-IPCountry` header first (Cloudflare provides this)
2. Fall back to `X-Real-IP` + GeoLite2 lookup
3. Cache results in Redis (TTL: 24h per IP)
4. Default to "unknown" if no geo data available

#### 2C. Geo Middleware in Gateway
**Files to modify:**
- `services/gateway/api-gateway/src/modules/proxy/proxy.controller.ts` — Add geo-check middleware

**Logic:**
1. Resolve user's country from request
2. For content endpoints (`/content/*`, `/reality/*`, `/movies/*`, etc.), check geo restrictions
3. Pass country code as `X-User-Country` header to backend services
4. Backend services use country for filtering (not gateway-level blocking, to allow admin overrides)

#### 2D. Content Filtering in Access Control
**Files to modify:**
- `services/core/content-service/src/modules/content/access-control.service.ts` — Add geo check to `checkContentAccess()`

**Logic:**
1. After checking content status, check `allowedCountries` and `blockedCountries`
2. If user's country is in `blockedCountries`, deny access
3. If `allowedCountries` is non-empty and user's country is not in it, deny access
4. Check `minAge` against user's date of birth (from user-profiles)

#### 2E. Admin Geo Management
**Files to modify:**
- `services/core/content-service/src/modules/admin/admin.controller.ts` — Geo restriction CRUD
- `apps/admin/client/src/routes/geo-restrictions.tsx` — Admin UI

## Feature 3: Device Limits Based on Subscription

**Goal:** Limit concurrent device streams per subscription tier, with device registration and management.

### What Exists
- `SubscriptionPlan` model has `tier` field (free, basic, premium, enterprise)
- `Session` model in auth-service tracks devices (deviceName, deviceType, os, browser, ipAddress)
- No device limit enforcement
- No concurrent session tracking

### Implementation

#### 3A. Subscription Plan Device Limits
**File to modify:** `services/engagement/subscription-service/prisma/schema.prisma`

**Add to SubscriptionPlan:**
```prisma
maxDevices      Int      @default(1)  // Max concurrent devices
maxStreams       Int      @default(1)  // Max concurrent streams
```

**Default limits by tier:**
| Tier | Max Devices | Max Streams |
|------|------------|-------------|
| Free | 1 | 1 |
| Basic | 2 | 2 |
| Premium | 5 | 5 |
| Enterprise | 10 | 10 |

#### 3B. Device Registration Model
**File to modify:** `services/core/auth-service/prisma/schema.prisma`

**New table:**
```prisma
model RegisteredDevice {
  id            String   @id @default(uuid())
  userId        String
  deviceName    String
  deviceType    String   // "mobile", "web", "desktop", "tablet"
  os            String?
  browser       String?
  fingerprint   String?  // Device fingerprint hash
  isTrusted     Boolean  @default(false)
  lastActiveAt  DateTime @default(now())
  registeredAt  DateTime @default(now())
  revokedAt     DateTime?
  user          User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@index([userId])
  @@index([userId, isTrusted])
  @@map("registered_devices")
}
```

**Add to User model:**
```prisma
devices RegisteredDevice[]
```

#### 3C. Device Limit Service
**New file:** `services/core/auth-service/src/modules/device/device-limit.service.ts`

**Logic:**
1. When user logs in or starts a stream, check active devices against subscription limit
2. Query `RegisteredDevice` where `revokedAt IS NULL` and `lastActiveAt > 5 minutes ago`
3. If count >= limit, deny new session or prompt to revoke oldest device
4. Expose `GET /auth/devices` (existing), `POST /auth/devices/register`, `DELETE /auth/devices/:id`

#### 3D. Subscription-Aware Device Check
**Files to modify:**
- `services/engagement/subscription-service/src/modules/subscription/subscription.service.ts` — Add device limit to plan queries
- `services/core/auth-service/src/modules/auth/auth.service.ts` — Check device limit on login

**Flow:**
1. User logs in → always allowed (login is never blocked)
2. Register device on login
3. When user attempts to play video content → check active streams against subscription limit
4. If under limit → allow streaming
5. If at limit → block streaming, return `deviceLimitReached` error, show device management UI
6. User can revoke a device via `DELETE /auth/devices/:deviceId` to free a slot

#### 3E. Device Management UI
**Files to create/modify:**
- `apps/web/src/app/settings/devices/page.tsx` — Already exists, enhance with device limit display
- `apps/mobile/app/(tabs)/settings/devices.tsx` — New screen for device management

**Components:**
- List of registered devices with last active time
- Revoke device button
- Device limit indicator (e.g., "2 of 5 devices used")
- Upgrade prompt when at limit

## Feature 4: Platform-Wide Feature Suggestions

**Goal:** Identify and plan high-impact features across the entire platform.

### Suggested Features (Prioritized by Impact)

#### P0 — Revenue Impact
1. **Pay-Per-View Events** — Live ticketed events with real-time streaming (extends screening system)
2. **Creator Tipping tiers** — Allow custom tip amounts with leaderboard for top tippers
3. **Bundle Passes** — Discounted passes combining multiple universes (e.g., "Entertainment Bundle": Reality + Comedy + Movies)

#### P1 — Engagement Impact
4. **Social Sharing Rewards** — Earn points for sharing content to social media
5. **Watch Parties** — Synchronized viewing with friends (WebSocket-based)
6. **Push Notification Campaigns** — Admin-created targeted notification campaigns (infrastructure exists in notification-service)
7. **Content Playlists** — User-curated playlists (like YouTube playlists)

#### P2 — Platform Quality
8. **Offline Downloads** — Allow premium users to download content for offline viewing
9. **Multi-Language Support** — i18n for UI and content subtitles
10. **Dark Mode Toggle** — Already in user_preferences, needs UI implementation
11. **Content Reporting Improvements** — Detailed report categories with auto-moderation

#### P3 — Growth
12. **Referral Leaderboard** — Public leaderboard of top referrers with prizes
13. **Creator Verification Badges** — Visual badges for verified creators
14. **Content Collaborations** — Allow multiple creators to co-author content
